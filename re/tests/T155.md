## Question
What value does the shipped game use for PhysicsWorld.maxLargeGeoms (setting present in the engine settings store, or the 2000 default)?

## Hypothesis
`Game_Read_PhysicsWorldConfig` (0x144457220, sig game.read_physics_world_config) reads PhysicsWorld.maxLargeGeoms with `Ne_Map_FindOrDefaultWithErrorContext` (0x143a42f10, sig core.map_find_or_default_with_error_context) at 0x1444576f5, default 0x7d0 = 2000. The key string is only in the exe and no static writer of the settings store was found, so the default is expected: return value 2 (missing) and 2000 written to the out pointer. The VCQTC collision tiles are created from this pool (`Ne_MoverCollision_BuildMoverShapes`), so the value is the real per-track tile budget.

## Promotes
- `Game_Read_PhysicsWorldConfig` notes: shipped maxLargeGeoms value (L3 for that note).
- `Ne_Map_FindOrDefaultWithErrorContext`: return code 2 = key missing, default written (L3).

## Trace config
Hook `core.map_find_or_default_with_error_context` (entry + return). On entry log the key string (rdx, C string) only when it starts with `PhysicsWorld.`, keep r8 (out pointer) and r9d (default); on return log eax and the u32 at the saved out pointer. Only the first call per key is needed (the reader runs at world init).

## Expected log lines
- `PhysicsWorld\.maxLargeGeoms .*default=2000 .*rc=2 .*value=2000` -> proves the shipped value is the code default.
- `PhysicsWorld\.maxLargeGeoms .*rc=0 .*value=(\d+)` -> proves a settings source sets it; the number is the shipped value.
Pass rule: one maxLargeGeoms line with a value. Fail rule: no PhysicsWorld line at all (wrong hook) -> inconclusive.
