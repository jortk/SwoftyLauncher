# T221 Which physics material does an unknown collision ground code resolve to, and does it carry MECHANICS?

- Requested by: engine-re, 2026-11-17
- Status: draft
- Session: (filled by the lead when batched)

## Question
For a VCQTC tile whose material id is not in the physics MATERIALS library, which library entry (code) does the wheel end up on, and is wheel+0x200 (MECHANICS) null or not?

## Hypothesis
Static (d873a1c8): `Ne_MoverCollision_BuildMoverShapes` 0x1440caa60 resolves an unknown or zero id to the FIRST library entry (and records NEerrno 2). `Car_Contact_QueryWheels` then takes MECHANICS = entry + extension offset. If entry 0 has a MECHANICS block (likely DEFA, which the barrier-impact dump lists), the car drives with DEFA grip/slowdown, not with the "no record -> grip 1.0" fallback of `Car_Surface_SampleAt`.

## Promotes
- `Ne_MoverCollision_BuildMoverShapes` (material resolution note), `Car_Contact_QueryWheels` (MECHANICS pointer note)

## Build
- exe: F1_25.exe sha256 d873a1c8d2044cef…
- plugins: swofty core with a read-only probe after `Car_Contact_QueryWheels` (log per player wheel: [wheel+0x208] code, wheel+0x200 pointer, MECHANICS +0x50 fourCC, +0 grip, +0x78 ffb_surface).
- data: a test track package with one collision tile retagged to an unused code (e.g. `ZZZZ`).

## Trace config
Probe on the return of 0x1446d8cf0, player car only, once per second.

## User steps
1. Load the test package, Time Trial is not used (Grand Prix practice).
2. Drive slowly onto the retagged tile and stop on it for 5 s.

## Expected log lines
- `wheel code=<first library code> mech=<non-null> fourcc=<...> grip=<...>` on the retagged tile → proves the entry-0 fallback.
Pass rule: code equals library entry 0. Fail rule: null material or a different code.
