# T159 Which values does a lightmap-bound track instance receive from lightmap_locations at draw time?

- Requested by: engine-re, 2026-11-17
- Status: draft
- Session: (filled by the lead when batched)

## Question
For one known lightmap-bound instance (uniqueid known from its .layer file), which slice / size / u / v values from `eaid://ego_package/lightmap_locations` reach its draw constants, and what does an instance without an entry receive?

## Hypothesis
`Render_LightMapLocResFactory_Create` (0x143c06290) builds a map uniqueid -> {u32 slice, f32 size, f32 u, f32 v}; every model component holds this resource at +0xb8 and the radiance twin at +0xc0 (`Render_ModelComponent_Load`). Expected: the four values appear unchanged in a per-instance constant; a missing entry falls back to the default lightmap arrays (`eaid://default_lightmap_array_ao`).

Update 2026-11-17 (round 2, static): the consumer is now known. `Render_ModelComponent_SendLightMapData` 0x14446e5f0 posts message 0x16 with the values; the proxy stores them at +0x22..+0x3c (`Render_ModelProxy_HandleMessage` 0x143d405b0). The vertex shader reads them as `instanceBuffer` rows `+8` (AO) and `+9` (radiance). A missing entry sends zeros, and the shader then uses AO 1 and radiance 0 (size 0). The default-array hypothesis above is replaced by this. The capture now only confirms the two instanceBuffer rows of one known instance.
