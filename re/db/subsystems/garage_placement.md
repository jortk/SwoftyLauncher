The SDK backend accepts Steam build 26566308, SHA-256 `46009bd31f49d93a92d73cbd0b66131d2b37964a92da7293168d3c3a872d9389`. The observations below use RVAs on that executable. The separate Steam reference executable used for comparison has SHA-256 `d873a1c8d2044cef2fd76c99c9d5a97649c5b815d055540995105f46619865ae`. No runtime entry uses an RVA from this table.

The parked-car event runs synchronously after the native update. Each visit checks the current session's registered track, all occupied Pit entries and the captured owner's membership. Session termination invalidates all captures. The executable gate covers the complete set of operations. A successful comparison of one helper on the reference build does not enable that build.

## Individual roles and vehicle-only scene

Twelve installed 2024–2026 F1/F2 player and competitor scene definitions were compared. In the crew scene, human macros expand to a CharacterActor. The game's four wheel roles use the literal names `FL:`, `FR:`, `RL:` and `RR:`. `RJ:` is also colon-suffixed. F1 player scenes use `MB`, while F1 competitor and F2 scenes use `MB:`. F1 declares ten human roles. Its F2 counterpart declares six and omits all four wheel roles. ENG is distinct from EB2, which occurs in other game scenes. A clip referring to an EB2 actor cannot supply that actor to a garage from another scene. Prop and camera actor names never enter the role catalogue. Individual writes require a unique match on the current owner and an evaluated, non-root `Bip01` on that actor.

The Steam 26566308 spawner reads the literal `vehicle` at 0x56261c7 through `Game_Get_ModelNodeId` at 0x38ad6c–0x38ad78. It takes the resource actor count through the owner's vehicle scene at 0x38ad7a–0x38ad92, selects an actor from that scene at 0x38adfc–0x38ae07 and compares the matching definition's name at 0x38ae1f–0x38ae38. The selected actor enters the instance's parked-car field at 0x38ade2. The authored `garagecrew_vehicle` declares the single VehicleProxyActor named `vehicle`. The separate locator scene declares `vehicleLocater`. Before writing, the V2 operation requires the captured parked actor to be the sole entry of this vehicle scene, the same definition name and a scene distinct from the owner's crew, locator, equipment and gantry. Ambiguous parked-car updates shared by more than one bay are dropped.

With row-vector transforms, solve `currentCar × delta = requestedCar` and apply `currentVehicleScene × delta` to this scene. Native refresh propagates it. A later parked-car update reads the evaluated pose, including the game's cache. The offline tests exercise independent scene ownership, a non-trivial yaw/translation, refused aliases, write and refresh failure and deferred verification. These checks do not establish a visual result inside a protected game.
