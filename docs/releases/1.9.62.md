# 1.9.62

Swofty Launcher for F1 25 1.9.62 shows ads in the launcher, loads Time Trial and online session features from Swofty's server, and finds wheels and pads again in launches that start Proton on systems without SDL2.

## Launcher

- Ads show on the Home page, over the addon cards on Discover, at the top of an addon page's side column, on the Online page under the Time Trial filters, and while the game starts. A starting game keeps its ad until it has run for 30 seconds; slots close while the game runs.
- Signed-in supporters see no ads, and nobody signed in sees one until their support status has loaded. The supporter page lists no ads as a perk.
- On Linux, the `swofty-ads-helper` program hosts the ad slots.

## Time Trial

- The in-game Time Trial plugin (`swofty.tt`) comes from Swofty's server for a signed-in session. The launcher checks the server's signature before it places the plugin and caches it under `$DATA/modules`. `swofty run` prints `module tt-game: not loaded for this session: <reason>` when it is not there.
- Rival ghosts picked on an in-game leaderboard download.
- A sealed lap whose plugin files are not a published version goes to review.

## Online sessions

- Online session features load from Swofty's server as signed modules, checked and cached the same way.

## Controllers

- Launches that start Proton themselves (**Play** without the wrapper in the launch option, `swofty run --direct`, and the wrapper) find wheels and pads again on systems without SDL2, such as NixOS. Steam's 64-bit client has no `ubuntu12_32/steam-runtime` folder, so the launcher links the client's SDL3 (`steamrt64/libSDL3.so.0`) with the SDL2 layer from its runtime into `$DATA/state/runtime-libs`.

## Developers

- `SWOFTY_MODULE_<NAME>` overrides that place a local module build work only in debug builds.
- The overnight in-game suites (`tests/overnight`) are removed.
- CI retries runner package installs against the main Ubuntu archive when an EC2 regional mirror is missing a file.
